# IFC test fixtures (`ifcopenshell-project/files/`)

Sample IFC files used by the **Bonsai viewer**, **browser benchmark**, and **headless profiler**. They live at the workspace root (outside the `IfcOpenShell-webapp` git repo) so every tool loads the same models from a single place.

Vite apps serve this folder as static assets: files are available at the site root during dev and build, so `AC20-FZK-Haus.ifc` is at `/AC20-FZK-Haus.ifc`.

---

## How each tool uses these files

```
ifcopenshell-project/files/*.ifc
       │
       ├──► Bonsai viewer (bonsai-web-viewer)
       │    fetch("/AC20-FZK-Haus.ifc") on startup; file picker for any local .ifc
       │
       ├──► Browser benchmark (benchmarking/browser/)
       │    fetch("/AC20-FZK-Haus.ifc") by default; ?ifc=/5D.ifc to override
       │
       └──► Headless profiler (benchmarking/headless/)
            fs.readFileSync via --ifc=files/AC20-FZK-Haus.ifc
```


| File path on disk              | URL in browser              | Used by default in                               |
| ------------------------------ | --------------------------- | ------------------------------------------------ |
| `files/AC20-FZK-Haus.ifc`      | `/AC20-FZK-Haus.ifc`        | Viewer + browser benchmark default               |
| Any `files/*.ifc`              | `/<filename>.ifc`           | `headless/profile-all.mjs` (full suite)          |


**Path convention:** headless scripts take paths relative to **`ifcopenshell-project/`**, e.g. `files/AC20-FZK-Haus.ifc`. Browser code uses web URLs starting with `/`.

## Quick commands (by tool)

### Interactive viewer

```powershell
cd IfcOpenShell-webapp\src\bonsai-web-viewer
npm run dev
# Opens http://localhost:4174 — loads /AC20-FZK-Haus.ifc automatically
# Or load sidecar directly (no WASM tessellation):
# http://localhost:4174/?ifc=/test_sidecar.ifcview
# Paired sidecar auto-load: put AC20-FZK-Haus.ifcview beside AC20-FZK-Haus.ifc — viewer tries it first
```

Use the file picker to load any local IFC; fixtures in this folder are optional shortcuts.

### Browser benchmark

```powershell
cd benchmarking
npm install
npm run browser:dev
# http://localhost:4176/bench.html
# http://localhost:4176/bench.html?ifc=/AC20-FZK-Haus.ifc&runs=3
```

The benchmark loads the entire model's geometry in **one** WASM call (unlike the viewer/profiler which batch by 250).

### Headless profiler

```powershell
cd benchmarking
npm run profile -- --ifc=files/AC20-FZK-Haus.ifc
npm run profile:all
```

## Adding or replacing fixtures

1. Copy the `.ifc` file into this directory.
2. **Viewer / benchmark:** reference it as `/<filename>.ifc` in the URL or change the default constant in source.
3. **Profiler:** run with `--ifc=files/<filename>.ifc`.
4. **Suite:** `profile-all.mjs` picks up any new `.ifc` automatically.

Keep files reasonably sized for CI if you run `profile:all` regularly. Very large models (e.g. `roche.ifc`, `Works-LIVE.ifc`) can take minutes for full geometry profiling.

## Golden fixtures for sidecar / RDBView gates (Gate 0+)

Decision gates (D1 sidecar reader, D3 rdbview unpack) need **desktop-exported** derived formats alongside the `.ifc` sources. These are not checked into git by default (large binaries).

### Required exports (minimum 3 models)

| IFC source | Export `.ifcview` | Export `.rdbview` | Used by |
|------------|-------------------|-------------------|---------|
| `AC20-FZK-Haus.ifc` | `AC20-FZK-Haus.ifcview` | `AC20-FZK-Haus.rdbview` | Viewer + harness default |
| `window_wall.ifc` | `window_wall.ifcview` | `window_wall.rdbview` | Headless warmup + wall/window geometry |
| `5D.ifc` | `5D.ifcview` | `5D.rdbview` | Medium-model regression |

### How to export (Bonsai Viewer / ifcviewer2)

1. Open the `.ifc` in desktop Bonsai Viewer.
2. **Sidecar:** export or generate paired `foo.ifcview` (stem rule: same basename as `.ifc` or `.rdb/`).
3. **Bundle:** export `foo.rdbview` (ZIP containing `model.ifcview` + `model.rdb/` per `exportGeometryDatabase()` layout).
4. Copy outputs into this `files/` directory.

### Verify harness (after export)

```powershell
cd benchmarking
npm run profile:sidecar -- --fixture=files/window_wall.ifcview
npm run profile:rdbview -- --fixture=files/AC20-FZK-Haus.rdbview
npm run profile -- --ifc=files/AC20-FZK-Haus.ifc --decision-v1
```

Stub profilers emit `ifcweb-decision-v1` JSON under `benchmarking/headless/out/` even when fixtures are missing (`status: missing-fixture`).
